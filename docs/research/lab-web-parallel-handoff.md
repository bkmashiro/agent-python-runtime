# Pysolate Lab Web Parallel Handoff

**Status:** Accepted direction; Lab v1 schema is not frozen until Track B of the active roadmap passes schema tests and independent review.

**Active Runtime roadmap:** `.hermes/plans/2026-08-12_095911-workload-evaluation-lab-contract-megagoal.md`

## Worktree rule

The Web implementation must use a separate Git worktree/branch or a separate repository. Do not run two writers in `/Users/yuzhe/projects/agent-python-runtime`.

Suggested setup:

```bash
git -C /Users/yuzhe/projects/agent-python-runtime worktree add \
  /Users/yuzhe/projects/agent-python-runtime-lab-web \
  -b feat/lab-web-v1 main
```

If the UI is intentionally a separate repository, record the exact Runtime schema commit in its fixture manifest.

## Ownership

The Runtime/evaluation session owns:

- `schemas/lab/**`
- Lab v1 Go producer/validator types
- `runtime/**`
- `research/labstore/**`
- `research/operator/**`
- canonical JSON fixtures and their hashes
- the active roadmap

The Web session owns only its UI application, generated client types, fixture adapters and presentation tests. It must not modify canonical schemas or Runtime/Store behavior to make UI code easier.

## Draft phase

Before schema freeze, the Web session may build visual prototypes against fixtures labelled:

```json
{
  "schema_version": "pysolate.lab-draft.v0",
  "fixture_only": true
}
```

Draft fixtures are not evidence of Runtime compatibility and must not be described as Current data paths.

## Lab v1 minimum views

The frozen contract will provide bounded read shapes for:

1. study/index overview;
2. run detail;
3. ordered timeline page;
4. counterfactual branch DAG;
5. workspace metadata diff;
6. run comparison;
7. typed object references;
8. structured problems/errors.

The UI should display truncation, incomplete evidence, experimental status, privacy/export state and prohibited claims explicitly. It must not fetch or render protected prompt/code/provider/workspace bodies by default.

## Compatibility rule

After freeze:

- adding optional fields with fixtures and validators may remain v1;
- changing requiredness, enum meaning, identity semantics, pagination or privacy behavior requires v2;
- digest references are not authorization;
- portable does not mean public or harmless;
- missing/private objects fail closed and remain visible as structured unavailable states.

## First integration gate

Do not claim integration until the Web session consumes canonical fixtures generated by the committed Go producer and passes:

- strict schema validation;
- unknown enum/field fallback behavior;
- empty and truncated states;
- incomplete-evidence state;
- private/unavailable object state;
- branch DAG and workspace diff rendering;
- mobile and desktop smoke if the chosen framework supports them.
