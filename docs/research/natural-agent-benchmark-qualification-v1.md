## Decision

Use the text half-duplex core of `tau2-bench` as the **primary natural Agent benchmark source** for Pysolate's bounded evaluation campaign.[1]

Begin with the `airline` domain and preserve its task, policy, user-simulator, environment-state and official evaluator contracts. The Pysolate treatment changes only the Agent action representation:

```text
direct baseline:       assistant tool-call objects → tau2 environment
Pysolate treatment:    assistant ordinary Python → sealed Plan/Broker → tau2 environment adapter
```

Do not publish Pysolate treatment scores as directly comparable official leaderboard scores. The programmatic-Python interface is a deliberate treatment. Report paired task IDs, model/prompt contract, user-simulator seed, direct baseline, treatment result and interface difference.

Retain ToolSandbox as a secondary stress-corpus candidate, not the first integration target. Treat AssistantBench and GAIA as VM/Computer placement controls rather than the primary bounded-runtime cohort.[2][3][4]

## Why `tau2-bench` is the primary source

At the audited revision:

- the project is MIT licensed and declares version `1.0.1`;
- the text benchmark models a stateful interaction among Agent, user and environment;
- tasks carry initialization data, action references and evaluation criteria;
- the evaluator can combine database state, communicated information, environment assertions and optional natural-language assertions;
- domain tools already distinguish `READ`, `WRITE` and `GENERIC` categories;
- the core domains include airline, retail and telecom;
- the framework supports user-side information that is revealed through conversation rather than being placed in the initial Agent prompt.

These properties are relevant to Pysolate because they permit independent task-state oracles, multi-turn information acquisition, read/write boundaries and policy-sensitive tool use without requiring a live production provider.[1]

They do **not** prove that `tau2-bench` tool types can be copied directly into Pysolate capability declarations. Pysolate's Host must independently derive and validate every canonical `capability.Spec`.

## Candidate comparison

| Candidate | Relevant strengths | Boundary/problem | Decision |
|---|---|---|---|
| `tau2-bench` | Stateful domain DB, user interaction, typed READ/WRITE tools, policies, task-level state and communication evaluation, active MIT codebase | Direct tool-call benchmark rather than Agent Python; WRITE mapping requires an honest private-state contract | **Primary** |
| ToolSandbox | Device-like life tasks, state dependencies, user simulator, tool allow/deny lists, milestone DAG, minefields and trajectory-independent evaluation | Older/heavier Python stack; manually derived tool effect contracts; higher adapter cost; Apple sample-code terms rather than MIT | Secondary stress corpus only |
| AssistantBench | Realistic, long-running web assistant tasks across many sites | Browser navigation and live-web state dominate; requires a Computer/browser environment rather than bounded Python | VM/Computer placement control |
| GAIA | General-assistant questions involving reasoning, files, multimodality, web browsing and tools | Mixed browser/multimodal/native requirements make it a placement benchmark, not a clean effect-compiler evaluation | VM/Computer placement control |
| Open-SWE/coding corpora | Real repositories, shell and test oracles | Repository setup, package managers, subprocesses and native dependencies normally justify VM placement | Keep `attrs-770` only as a separate exact pure-Python case study |

## Interface preservation contract

The adapter must preserve:

1. exact upstream task ID and initialization data;
2. exact policy text presented to the Agent;
3. exact user-simulator behavior and seed;
4. exact tool argument and result semantics;
5. one isolated upstream environment/database per row;
6. exact upstream terminal environment state;
7. official upstream evaluator inputs and outputs;
8. complete direct-baseline and Pysolate-treatment trajectories;
9. independent Pysolate source/Plan/receipt/workspace evidence;
10. failures and unsupported rows in the denominator.

The adapter may change only:

- the Agent-facing representation from tool-call JSON to ordinary Python;
- the Host-owned binding from upstream tool definitions to sealed Pysolate capability specs;
- collection of Pysolate-specific causal evidence.

The adapter must not:

- reveal reference actions or expected values to the Agent;
- edit benchmark policy to make a task easier;
- replace official environment-state evaluation with Runtime receipts;
- silently repair malformed Agent Python;
- retry after a possibly started WRITE;
- omit failed, rejected or unsupported rows;
- claim official leaderboard comparability.

## Effect mapping gate

### READ tools

A `tau2` READ tool may become a Pysolate `external_read` capability only after the adapter verifies:

- no task-state mutation;
- bounded typed arguments/results;
- Host-owned resource identity;
- deterministic isolated environment selection;
- no provider credentials exposed to the Guest;
- correct freshness and playback declaration;
- Broker call and receipt attribution.

A source-bound pre-dispatch decision requires the stricter existing legality contract. The adapter does not make every READ pre-dispatchable.

### WRITE tools

`tau2` WRITE does **not** automatically map to an existing Pysolate effect class.

The current runtime has no production `external_write` transaction/reconciliation plane. A benchmark WRITE may map to `workspace_write` only if T1 proves all of the following without runtime weakening:

- the entire benchmark world for the row is an attempt-private Host-owned state object;
- no live provider or shared external state is mutated;
- state cannot escape before the independent oracle runs;
- reject, cancellation and failed execution discard the attempt state;
- the final state and disposition join the Pysolate evidence model honestly;
- the capability declaration matches actual handler behavior.

If these properties cannot be established with existing runtime contracts, WRITE rows are `unsupported_effect_class`; they are retained in the denominator and no new production external-write feature is added.

Approval does not make a misclassified effect safe. Approval is an additional authority gate, not an effect-type substitute.

## Canary set

### Canary A — bounded READ and communication

```text
domain: airline
task_id: 3
reference actions:
  - get_reservation_details
  - get_user_details
required communicated value: "4"
reward basis: DB + COMMUNICATE
```

Purpose:

- validate exact task and policy projection;
- bind two Host-declared READ capabilities;
- execute ordinary Agent Python in a real Guest;
- return tool results through the same Broker;
- let the Agent compute/communicate the answer;
- join official task oracle with source, Plan, logical calls and physical calls;
- compare direct and programmatic treatments.

This is the first row to execute.

### Canary B — multi-turn wait and attempted WRITE

```text
domain: airline
task_id: 11
reference action:
  - update_reservation_flights
required communicated value: "5244"
reward basis: DB + COMMUNICATE
```

The user withholds the reservation ID for the first two interaction rounds and later supplies `GV1N64`.

Purpose:

- validate that ordinary conversation waiting is represented as turn-level/fresh-Run state, not falsely called same-continuation suspension;
- test the honest WRITE effect-mapping gate;
- if admissible as private benchmark workspace state, run approval accept and reject lanes;
- independently inspect final benchmark DB state;
- prove that reject/expiry performs no physical handler dispatch.

This row is a stop gate. Do not execute its WRITE through Pysolate until the attempt-private state contract is proven.

The read-only boundary audit is recorded in [tau2-airline-11-write-boundary-v1.json](../evidence/tau2-airline-11-write-boundary-v1.json), identity `sha256:37c302dac7cca7788279beeee53e990a5552a97b5933dc906a196c6bfac39fea`.

Observed positive facts:

- independent upstream Environment constructors produce distinct DB and target-reservation objects with the same initial hash;
- the reference action is an upstream-declared mutating WRITE;
- the official Environment evaluator constructs independent predicted and gold worlds.

Blocking gaps in the current Pysolate treatment:

- the task world is not bound to a Pysolate workspace attempt/disposition;
- the existing exact adapter has no task-11 or cross-turn persistent WRITE state;
- no current effect contract honestly describes the Host in-memory task-world mutation;
- final task-world state is not joined to workspace/effect disposition evidence;
- cancel or failed execution has no proved discard contract for an attempted task world.

Decision at the audit boundary: `unsupported_effect_class`. That v1 artifact remains the honest pre-implementation result; no model trial or WRITE dispatch occurred during the audit.

### Bounded private-WRITE closeout

The later, task-specific implementation is recorded in [tau2-airline-11-private-write-canary-v1.json](../evidence/tau2-airline-11-private-write-canary-v1.json), report SHA-256 `17a9e03165185684723cff1dcf48166355a9821e88da1aafe908b2b61a4c4335`.

It does not add a production `external_write` effect or a generic tau2 adapter. Instead, one authored zero-argument capability freezes the exact task-11 reference operation in its Grant through `operation_sha256`. Each lane forks a real Pysolate private workspace attempt containing a fresh task-world snapshot. The Host adapter applies the real upstream mutation to a candidate state and installs it atomically only after a successful response.

Four real WASM Guest/Broker controls passed:

| lane | approval | handler calls | state change | receipt | workspace disposition |
|---|---:|---:|---:|---|---|
| accepted | approved/executed | `1` | yes | `ok` | published |
| rejected | rejected/not executed | `0` | no | `denied` | discarded |
| expired | expired/not executed | `0` | no | `denied` | discarded |
| injected failure | approved/executed | `1` | no | `error` | discarded |

For the accepted lane, the receipt response digest independently recomputes from the private tool content, frozen operation digest, and final task-world digest. The private workspace's actual final FlightDB is also supplied to the oracle and its upstream DB hash matches the independently built official gold environment. The official tau2 `EnvironmentEvaluator` and `CommunicateEvaluator` independently replay the same operation semantics (task, tool, arguments and content), under a distinct oracle call identity, and both return `1.0`.

Classification: `SUPPORTED_BENCHMARK_PRIVATE_ONLY`. This supports one exact, authored, authority-gated mutation through the real Guest and Broker. It does not support model WRITE ability, a leaderboard result, generic rollback, or production external effects.

The public report is rebuilt from the private authored source, canonical sealed Plan documents, Grant policy, Guest request/response bodies, receipts, approval records, workspace disposition events, accepted final state and oracle request/report. It independently recomputes source/document/occurrence/receipt/Grant/Plan/body identities and rejects tampered or non-body-safe fields.

### Negative oracle control — no-op sensitivity

```text
domain: airline
task_id: 1
```

The audited task has READ reference actions but empty `communicate_info`, while its reward basis is DB + COMMUNICATE. Because the expected DB state is unchanged, a no-op trajectory can be insufficiently distinguished by the official programmatic reward.

Purpose:

- prove that official scalar reward alone is not accepted as evidence;
- require action/communication/effect diagnostics alongside reward;
- prevent post-hoc selection of high-scoring but non-discriminating tasks.

Do not count this row as a positive canary success.

## Pure/no-authority task closeout

The body-safe result is [tau2-pure-natural-task-qualification-v1.json](../evidence/tau2-pure-natural-task-qualification-v1.json), report SHA-256 `b5fdc9797ec0eb076392b10ccd0f061728c6637af234a0adcec6df15bb2f1b78`.

This component is not the task's default overall reward basis, so the report does not call it an official task score.

The natural trajectory issued two READ tool calls and received component reward `0.0`. It therefore failed the preregistered no-tool criterion. This is `SUPPORTED_MECHANISM_ONLY`: it proves the zero-authority runtime path, not a successful natural pure-task row.

Conclusion: `NO_ELIGIBLE_PURE_NATURAL_TASK` under this exact selection contract. The negative row closes T1 honestly; it does not claim that tau2 has no pure task under every possible model-based or non-deterministic oracle contract.

### T2 recorded outcome

The authorized run retained all 32 preregistered rows in [tau2-t2-cohort-v1.json](../evidence/tau2-t2-cohort-v1.json), SHA-256 `1b39af87cffe8daffb13f422cca6af5e8162652abdd265433e7d0a9aba85d252`. Direct produced 16 completed official SimulationRuns. Programmatic Python produced seven completed, eight unscorable and one not-recorded row. The eight unscorable rows comprise seven empty AssistantMessage contract failures and one preregistered provider-budget exhaustion. The not-recorded row was interrupted by the outer orchestration timeout after provider work may have begun; its provider count and reward remain unknown. Known provider invocations total 328.

This run exposed a causal-evidence storage defect rather than a positive Runtime result. Dynamic turns used shared `turn-XX-guest-{request,response}.json` names under the cohort root, so later tasks overwrote earlier raw bodies. The strict aggregate detects duplicate references before validating turns. It assigns zero source joins to collided turns and labels six completed treatment rows `not_recorded_shared_raw_path`; only one completed treatment row has independently reconstructed source/Plan/Grant/receipt/body joins. The preregistered no-rerun rule prevents repairing paths and repeating affected cells.

The public outcome is therefore `NATURAL_BOUNDED_COHORT_RECORDED_WITH_EVIDENCE_GAPS`. Official completed-task rewards remain factual model/task observations. They do not support a matched-surface performance comparison, leaderboard claim or cohort-level source-bound Runtime mechanism claim. The earlier `airline/3`, WRITE authority and authored pure-mechanism canaries remain the valid mechanism evidence.

## Observed DeepSeek paired interface canary

The body-safe result is [tau2-airline-3-deepseek-paired-canary-v1.json](../evidence/tau2-airline-3-deepseek-paired-canary-v1.json).

The preregistered configuration used `deepseek/deepseek-chat` for both Agent and user simulator, seed `42`, temperature `0`, task `airline/3` and one bounded trial per lane. The result is `PAIR_NOT_COMPARABLE`:

- the direct lane produced an official `tau2` simulation with reward `0.0` and termination `agent_error` after the provider response contained both assistant content and a `get_user_details` tool call, violating the upstream half-duplex message contract;
- the treatment model did not produce an admissible strict JSON program action; adapter setup exposed two exception-classification defects before the scoring attempt reached upstream protocol validation;
- the scoring attempt remained unscorable because upstream validation raised rather than returning a `SimulationRun`;
- no model-authored Python reached source admission, no Pysolate tool Run started and no physical effect was issued in the treatment lane.

This is model/interface qualification evidence, not a Runtime comparison. Neither failure is attributed to Pysolate, and no direct-versus-treatment performance claim is supported. A future paired trial requires a prior format canary proving both pure function-call output in the direct lane and strict program-action output in the treatment lane.

### DeepSeek V4 Pro resolution

The follow-up body-safe result is [tau2-airline-3-deepseek-v4-pro-paired-canary-v1.json](../evidence/tau2-airline-3-deepseek-v4-pro-paired-canary-v1.json).

Provider-format qualification showed that the legacy `deepseek-chat` alias consistently emitted non-empty assistant content with a tool call, while the current V4 models separated reasoning from the assistant content field. Treatment also required the provider's native JSON response mode rather than a prompt-only JSON request. The bounded paired rerun therefore used `deepseek/deepseek-v4-pro` for both Agent and user simulator with the same task, seed `42` and temperature `0`.

Observed result:

- direct official reward: `1.0` (`DB=1.0`, `COMMUNICATE=1.0`), terminating with `user_stop`;
- treatment official reward: `1.0` (`DB=1.0`, `COMMUNICATE=1.0`), terminating with `user_stop`;
- direct actions: `get_reservation_details`, `get_user_details`, then `transfer_to_human_agents`;
- treatment: two model-authored single-tool Python programs, two logical calls, two physical calls and two terminal `ok` receipts;
- both treatment receipts carry distinct `source_bound` occurrences, and both Broker response identities match the exact results returned to the model;
- no direct benchmark tool call was leaked from the treatment Agent into the official environment trajectory.
- the tool surfaces are intentionally not matched: direct retained the full upstream airline tool set and selected `transfer_to_human_agents`, while treatment remained limited to the two preregistered READ adapters.

Conclusion: `PAIRED_CANARY_SUPPORTED`. This supports the N=1 read-only adapter correctness and causal-evidence wiring claim. It does not support a fair tool-surface comparison, a latency/performance claim, a WRITE claim, or official leaderboard comparability; the two interactive trajectories share model/configuration but need not be message-for-message identical.

## Row schema additions

Each row must retain:

- upstream repository revision;
- benchmark/domain/task ID;
- user-simulator seed and trial index;
- model and prompt-contract identity;
- treatment (`direct` or `pysolate_programmatic`);
- exact Agent source digest and private source reference;
- capability Plan and profile identities;
- effect mapping decision and rejection reason;
- official reward components, not scalar reward alone;
- independent final-state oracle status;
- logical and physical call counts;
- approval/wait/placement dispositions;
- evidence join completeness;
- terminal status: completed, rejected, routed, unsupported, unclassifiable or failed.

Task bodies, model messages, source bodies, tool results and database snapshots remain private evidence. Public reports contain IDs, digests, categorical outcomes and aggregates only.
