## Decision

Use the text half-duplex core of `tau2-bench` as the **primary natural Agent benchmark source** for Pysolate's bounded evaluation campaign.[1]

Begin with the `airline` domain and preserve its task, policy, user-simulator, environment-state and official evaluator contracts. The Pysolate treatment changes only the Agent action representation:

```text
direct baseline:       assistant tool-call objects → tau2 environment
Pysolate treatment:    assistant ordinary Python → sealed Plan/Broker → tau2 environment adapter
```

Do not publish Pysolate treatment scores as directly comparable official leaderboard scores. The programmatic-Python interface is a deliberate treatment. Report paired task IDs, model/prompt contract, user-simulator seed, direct baseline, treatment result and interface difference.

Retain ToolSandbox as a secondary stress-corpus candidate, not the first integration target. Treat AssistantBench and GAIA as VM/Computer placement controls rather than the primary bounded-runtime cohort.[2][3][4]

## Why `tau2-bench` is the primary source

At the audited revision:

- the project is MIT licensed and declares version `1.0.1`;
- the text benchmark models a stateful interaction among Agent, user and environment;
- tasks carry initialization data, action references and evaluation criteria;
- the evaluator can combine database state, communicated information, environment assertions and optional natural-language assertions;
- domain tools already distinguish `READ`, `WRITE` and `GENERIC` categories;
- the core domains include airline, retail and telecom;
- the framework supports user-side information that is revealed through conversation rather than being placed in the initial Agent prompt.

These properties are relevant to Pysolate because they permit independent task-state oracles, multi-turn information acquisition, read/write boundaries and policy-sensitive tool use without requiring a live production provider.[1]

They do **not** prove that `tau2-bench` tool types can be copied directly into Pysolate capability declarations. Pysolate's Host must independently derive and validate every canonical `capability.Spec`.

## Candidate comparison

| Candidate | Relevant strengths | Boundary/problem | Decision |
|---|---|---|---|
| `tau2-bench` | Stateful domain DB, user interaction, typed READ/WRITE tools, policies, task-level state and communication evaluation, active MIT codebase | Direct tool-call benchmark rather than Agent Python; WRITE mapping requires an honest private-state contract | **Primary** |
| ToolSandbox | Device-like life tasks, state dependencies, user simulator, tool allow/deny lists, milestone DAG, minefields and trajectory-independent evaluation | Older/heavier Python stack; manually derived tool effect contracts; higher adapter cost; Apple sample-code terms rather than MIT | Secondary stress corpus only |
| AssistantBench | Realistic, long-running web assistant tasks across many sites | Browser navigation and live-web state dominate; requires a Computer/browser environment rather than bounded Python | VM/Computer placement control |
| GAIA | General-assistant questions involving reasoning, files, multimodality, web browsing and tools | Mixed browser/multimodal/native requirements make it a placement benchmark, not a clean effect-compiler evaluation | VM/Computer placement control |
| Open-SWE/coding corpora | Real repositories, shell and test oracles | Repository setup, package managers, subprocesses and native dependencies normally justify VM placement | Keep `attrs-770` only as a separate exact pure-Python case study |

## Interface preservation contract

The adapter must preserve:

1. exact upstream task ID and initialization data;
2. exact policy text presented to the Agent;
3. exact user-simulator behavior and seed;
4. exact tool argument and result semantics;
5. one isolated upstream environment/database per row;
6. exact upstream terminal environment state;
7. official upstream evaluator inputs and outputs;
8. complete direct-baseline and Pysolate-treatment trajectories;
9. independent Pysolate source/Plan/receipt/workspace evidence;
10. failures and unsupported rows in the denominator.

The adapter may change only:

- the Agent-facing representation from tool-call JSON to ordinary Python;
- the Host-owned binding from upstream tool definitions to sealed Pysolate capability specs;
- collection of Pysolate-specific causal evidence.

The adapter must not:

- reveal reference actions or expected values to the Agent;
- edit benchmark policy to make a task easier;
- replace official environment-state evaluation with Runtime receipts;
- silently repair malformed Agent Python;
- retry after a possibly started WRITE;
- omit failed, rejected or unsupported rows;
- claim official leaderboard comparability.

## Effect mapping gate

### READ tools

A `tau2` READ tool may become a Pysolate `external_read` capability only after the adapter verifies:

- no task-state mutation;
- bounded typed arguments/results;
- Host-owned resource identity;
- deterministic isolated environment selection;
- no provider credentials exposed to the Guest;
- correct freshness and playback declaration;
- Broker call and receipt attribution.

A source-bound pre-dispatch decision requires the stricter existing legality contract. The adapter does not make every READ pre-dispatchable.

### WRITE tools

`tau2` WRITE does **not** automatically map to an existing Pysolate effect class.

The current runtime has no production `external_write` transaction/reconciliation plane. A benchmark WRITE may map to `workspace_write` only if T1 proves all of the following without runtime weakening:

- the entire benchmark world for the row is an attempt-private Host-owned state object;
- no live provider or shared external state is mutated;
- state cannot escape before the independent oracle runs;
- reject, cancellation and failed execution discard the attempt state;
- the final state and disposition join the Pysolate evidence model honestly;
- the capability declaration matches actual handler behavior.

If these properties cannot be established with existing runtime contracts, WRITE rows are `unsupported_effect_class`; they are retained in the denominator and no new production external-write feature is added.

Approval does not make a misclassified effect safe. Approval is an additional authority gate, not an effect-type substitute.

## Canary set

### Canary A — bounded READ and communication

```text
domain: airline
task_id: 3
reference actions:
  - get_reservation_details
  - get_user_details
required communicated value: "4"
reward basis: DB + COMMUNICATE
```

Purpose:

- validate exact task and policy projection;
- bind two Host-declared READ capabilities;
- execute ordinary Agent Python in a real Guest;
- return tool results through the same Broker;
- let the Agent compute/communicate the answer;
- join official task oracle with source, Plan, logical calls and physical calls;
- compare direct and programmatic treatments.

This is the first row to execute.

### Canary B — multi-turn wait and attempted WRITE

```text
domain: airline
task_id: 11
reference action:
  - update_reservation_flights
required communicated value: "5244"
reward basis: DB + COMMUNICATE
```

The user withholds the reservation ID for the first two interaction rounds and later supplies `GV1N64`.

Purpose:

- validate that ordinary conversation waiting is represented as turn-level/fresh-Run state, not falsely called same-continuation suspension;
- test the honest WRITE effect-mapping gate;
- if admissible as private benchmark workspace state, run approval accept and reject lanes;
- independently inspect final benchmark DB state;
- prove that reject/expiry performs no physical handler dispatch.

This row is a stop gate. Do not execute its WRITE through Pysolate until the attempt-private state contract is proven.

### Negative oracle control — no-op sensitivity

```text
domain: airline
task_id: 1
```

The audited task has READ reference actions but empty `communicate_info`, while its reward basis is DB + COMMUNICATE. Because the expected DB state is unchanged, a no-op trajectory can be insufficiently distinguished by the official programmatic reward.

Purpose:

- prove that official scalar reward alone is not accepted as evidence;
- require action/communication/effect diagnostics alongside reward;
- prevent post-hoc selection of high-scoring but non-discriminating tasks.

Do not count this row as a positive canary success.

## Observed authored canary

The body-safe result is [tau2-airline-3-canary-v1.json](../evidence/tau2-airline-3-canary-v1.json).

At the named source revision and real Guest artifact:

- two exact `external_read` capabilities were Host-authored, granted and sealed in one Plan;
- two authored ordinary-Python tool turns each ran in a fresh real WASM Guest, followed by one authority-free aggregation Run;
- both receipts terminated `ok` and logical/physical counts were `2/2`;
- the authored Runs produced answer `4`;
- the official upstream `EnvironmentEvaluator` and `CommunicateEvaluator` both returned `1.0`;
- the oracle's two tool-result contents hash exactly to the two Broker receipt response identities;
- public report regeneration was byte-stable;
- both programmatic receipts carry distinct exact `source_bound` occurrences and spans.

Conclusion: `SUPPORTED`. This validates the Host adapter, fresh-Run programmatic path, exact source-to-receipt join and independent official oracle. It is still an authored reference lane—not a natural model result—and does not test WRITE.

## Row schema additions

Each row must retain:

- upstream repository revision;
- benchmark/domain/task ID;
- user-simulator seed and trial index;
- model and prompt-contract identity;
- treatment (`direct` or `pysolate_programmatic`);
- exact Agent source digest and private source reference;
- capability Plan and profile identities;
- effect mapping decision and rejection reason;
- official reward components, not scalar reward alone;
- independent final-state oracle status;
- logical and physical call counts;
- approval/wait/placement dispositions;
- evidence join completeness;
- terminal status: completed, rejected, routed, unsupported, unclassifiable or failed.

Task bodies, model messages, source bodies, tool results and database snapshots remain private evidence. Public reports contain IDs, digests, categorical outcomes and aggregates only.
