# Hermes Runtime bridge

`apyrun-hermesd` is an opt-in local bridge for a standalone Hermes plugin. It does not modify Hermes, replace `execute_code`, start a provider, or discover a user profile.

```text
Hermes python_runtime plugin
  -> profile-private Unix socket
      -> apyrun-hermesd
          -> one compiled WASI CPython runtime
          -> single-use prepared slot
          -> required invocation trace SQLite
```

The initial bridge is intentionally local and narrow:

- Unix-domain socket only; no TCP listener;
- socket parent must already exist, be owned by the current user, and have mode `0700`;
- socket mode is `0600`, and an existing path is never replaced automatically;
- artifact and distribution manifest are clean absolute regular-file paths; schema v4 resolves only canonical sibling `import-inventory.json` and `import-qualification.json` files through the same pinned regular-file gate;
- manifest ABI, target, filename, size, source revision, artifact/manifest/sidecar SHA-256, profile/package identity, embedded-vs-sidecar equality, and qualified-subset-of-discoverable relation are verified before the socket becomes ready;
- no Host capability broker is configured, so Guest network/tool calls fail closed;
- one compiled runtime, one single-use prepared slot, and one concurrent invocation;
- per-invocation memory and execution-time bounds are Host flags;
- all execution identities are generated by the bridge and injected through `engine.WithInvocationRef`;
- every tool invocation requires `runtime.invocation.started` and `runtime.invocation.completed` persistence;
- trace payloads contain bounded identifiers, status, sizes, and digests only. Python source, inputs, results, prompt bodies, tool observations, and provider bodies are not persisted.

Hermes observer hooks are separate. They are fail-open by design and can provide only best-effort whole-Agent trace unless Hermes execution middleware is separately integrated and reviewed.

## Start an isolated bridge

Create a private directory belonging to an isolated Hermes profile or a disposable test root:

```bash
install -d -m 700 /absolute/private/runtime-dir

go run ./cmd/apyrun-hermesd \
  -artifact /absolute/dist/agent-python-runtime.wasm \
  -manifest /absolute/dist/manifest.json \
  -socket /absolute/private/runtime-dir/runtime.sock \
  -trace-db /absolute/private/runtime-dir/agent-trace.sqlite \
  -max-memory-mib 512 \
  -max-cpu-ms 20000 \
  -profile-imports json,math,statistics
```

Profile mismatch, unqualified Host policy, obvious undeclared static imports, and indeterminate source forms are rejected as `profile_unsupported` before trace start or runner checkout. The service uses `conservative-python-imports-v1` over the exact request source and defensively repeats the same admission from the Runner's bound properties. Dynamic import/execution, relative imports, lexical ambiguity, and comparison bounds overflow are not converted into Guest failures or backend fallback. The compatibility result records `syntax_checked=false`; no source result grants authority.

The bridge writes one readiness JSON object after artifact verification, trace-store opening, compilation, preparation, and private socket creation. Important fields include exact artifact/manifest digests, verified `artifact_profile`, `profile_admission`, Guest repository revision, active strategy, capacity, resource bounds, and explicit `network_capability:false` / `provider_mode:"none"` declarations. `-profile-imports` is optional Host policy; when present, every root must be present in the schema-v4 target-Guest qualified catalog, and every qualified root must remain present in the discoverable inventory, before the bridge binds policy and constructs the Runner. Roots are canonical, unique and comma-separated. Without it, `profile_admission:false` is reported and compatibility manifests fail closed because no Host profile is bound. Schema-v2/v3 bundles cannot enable profile admission.

The process owns only the supplied socket and trace paths. Shutdown closes the runtime/store and removes its own socket. It does not remove or replace stale paths from an earlier process.

## Protocol

Each connection carries one request and one response. Frames are an unsigned 32-bit big-endian length followed by bounded UTF-8 JSON. The maximum frame is 1 MiB. Unknown fields, duplicate keys, trailing JSON, forged `execution_id`, invalid identifiers, invalid JSON inputs/schema, NUL source, and Python source over 64 KiB are rejected.

The versioned operations are:

- `execute`: required Runtime invocation trace plus verified `ExecutionRef` evidence;
- `observe`: a strict metadata-only allowlist for best-effort Hermes lifecycle evidence.

`observe` accepts only agent-run start/completion, LLM response metadata, direct-tool completion metadata, a route in `direct|runtime|hybrid|none`, and final-state fingerprints. Payload fields are limited to digests, byte/character counts, bounded names/status, resource durations, counters, and token usage. There is no accepted field for raw prompt/provider bodies, reasoning, source code, tool arguments/results, attachment bodies, or secrets.

Execute request:

```json
{
  "version": "hermes-python-runtime-bridge/v1",
  "operation": "execute",
  "request_id": "request-1",
  "invocation": {
    "agent_run_id": "agent-run-1",
    "turn_seq": 1,
    "output_item_seq": 1,
    "segment_seq": 1,
    "invocation_id": "tool-call-1",
    "invocation_attempt": 1
  },
  "code": "result = inputs['left'] + inputs['right']",
  "inputs": {"left": 19, "right": 23},
  "requirements": [],
  "output_schema": {"type": "integer"}
}
```

`execution_id` is deliberately absent. The bridge creates it immediately before execution. The returned `execution_ref` must equal the requested Host coordinates plus that bridge-generated execution ID and the SHA-256 digest of the exact decoded Python source bytes. Any Runtime mismatch fails the tool call.

Successful response:

```json
{
  "version": "hermes-python-runtime-bridge/v1",
  "request_id": "request-1",
  "status": "ok",
  "result": 42,
  "metrics": {
    "capability_calls": 0,
    "result_bytes": 2
  },
  "execution_ref": {
    "agent_run_id": "agent-run-1",
    "turn_seq": 1,
    "output_item_seq": 1,
    "segment_seq": 1,
    "invocation_id": "tool-call-1",
    "invocation_attempt": 1,
    "execution_id": "execution-...",
    "executed_code_sha256": "sha256:..."
  }
}
```

Guest exceptions, schema mismatch, timeout, invalid Guest envelopes, execution-reference mismatch, and required-trace failure return bounded typed errors. A trace completion uses a short cancellation-independent context so timeout/cancel outcomes can still be durably recorded.

An optional non-empty `requirements` list uses the bounded feature vocabulary in [Structured unsupported and escalation outcome](unsupported-escalation.md). The bridge performs admission before trace start or Runner invocation. Unsupported requests return `status: "error"`, `error.code: "runtime_unsupported"`, and a Host-authored `outcome` containing `escalation_required`, sorted required features, `not_started` workspace/effect dispositions, and a request digest. No `execution_ref` is emitted because no execution exists.

An optional `compatibility` manifest names `base` or `numpy-core` and declared import roots. The pinned loader first validates the exact artifact profile, package set, artifact/manifest/inventory digests, sidecar contents, and build identity; when `-profile-imports` is configured, the Runner properties carry that artifact-bound Host profile and a defensive inventory copy. The bridge reconstructs it and rejects a mismatch with `error.code: "profile_unsupported"` before trace start or Runner invocation. It emits no escalation outcome or `execution_ref`: profile rejection is pre-execution placement information, not Hard escalation. This is explicit manifest plus Guest-discoverability admission, not source analysis or import-execution proof. See [Execution profile admission](profile-admission.md).

## Verification

Focused gates:

```bash
go test ./hermesbridge ./cmd/apyrun-hermesd ./agenttrace -count=1
go test -race ./hermesbridge ./cmd/apyrun-hermesd ./agenttrace -count=1
go vet ./...
go build ./cmd/...
GOOS=linux GOARCH=amd64 go build ./cmd/apyrun-hermesd
GOOS=linux GOARCH=arm64 go build ./cmd/apyrun-hermesd
```

A real smoke must use the exact pinned artifact, connect through the Unix socket, execute a deterministic no-capability request, read back `execution_ref`, reopen the SQLite trace read-only, and verify the socket disappears after shutdown. This proves local bridge mechanics only; it is not Hermes Agent E2E or provider performance evidence.
